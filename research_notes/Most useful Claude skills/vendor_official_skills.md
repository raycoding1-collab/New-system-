# Vendor-published (non-Anthropic) Agent Skills: most installed and most useful, as of 2026-11-02

How the data was collected (read this first):
- **skills.sh could not be reached from this session.** WebFetch to `skills.sh`, `www.skills.sh` and `lazyskills.sh` failed with DNS `ENOTFOUND` (the hosts are outside the session's allowed network domains). So no install count below was read directly off skills.sh.
- **Install counts come from a public daily mirror of skills.sh**: the LinklyAI/best-skills open-data repo (693 stars). Its 2026-11-02 snapshot (commit 2026-11-02T01:01:06Z) holds the skills.sh all-time, trending and hot lists (600 rows each), skills.sh's official flag, and an 8-week weekly-install series per skill. It was cloned and read here. Source files: [skills-sh.csv 2026-11-02](https://github.com/LinklyAI/best-skills/blob/main/data/2026-11-02/raw/skills-sh.csv), [skills-sh-official.csv 2026-11-02](https://github.com/LinklyAI/best-skills/blob/main/data/2026-11-02/raw/skills-sh-official.csv), [methodology](https://github.com/LinklyAI/best-skills/blob/main/docs/methodology.md). The mirror only covers the **top 600 all-time skills**, so anything below about 63,000 installs has no count.
- **Counting caveat from the methodology**: "Installs are **bundle-level**: installing a repo counts once for every skill in it." The count is deduplicated anonymous telemetry from the skills CLI, and manual `git clone` installs are not counted ([methodology](https://github.com/LinklyAI/best-skills/blob/main/docs/methodology.md)). So when every skill in a multi-skill repo has nearly the same count (Prisma, Azure, Firebase, Remotion's sub-skills), that is mostly people installing the whole repo. It is not separate demand for each skill.
- **GitHub stars, last push and license** come from the GitHub search API via `gh` on 2026-11-02, around 11:00 UTC. **Skill names, descriptions and skill lists** come from blob-less shallow `git clone`s of each repo on 2026-11-02, reading `SKILL.md` frontmatter. The `--skill` value is the frontmatter `name`, which is sometimes different from the folder name.
- The "weekly" figure is the last value in the mirror's 8-week `weekly_installs` series. The column order (oldest to newest) is assumed, not documented.

### Inferences
- The owner total for vercel-labs (3.19M) is lower than find-skills alone (4.16M), so the owner totals are computed on a different basis or window. Use skill-level numbers, not owner totals.
- Inside vercel-labs/agent-skills the counts spread widely (861k down to 114k). That suggests people mostly install single skills with `--skill`, so the ranking there reflects real per-skill demand. Compare Prisma or Azure, where whole-repo installs produce flat clusters.
- For a website or design project, the strongest Vercel picks are web-design-guidelines (an audit checklist) and vercel-react-best-practices (only if the site is React or Next.js). vercel-react-view-transitions and deploy-to-vercel / vercel-cli-with-tokens fit specific needs. Do not install anything from vercel-labs/next-skills.

### Gaps
- The skills.sh pages themselves (security-audit badges, exact current counts) could not be opened (DNS blocked). Counts are mirror values from 2026-11-02, not first-hand.
- The repo-level license of vercel-labs/agent-skills is unclear: there is no LICENSE file, and 4 of the 9 skills declare MIT in their frontmatter.
- vercel/next.js skills, json-render and agent-browser's sub-guides have no install counts because they are below the top 600 or not listed.

## Q4. Which vendor skills fit a static-HTML / React / Next.js website and design workflow, and where do they overlap with what this project already has?

### Inferences
- Shortlist for this project, in priority order, using the project install form `npx skills add <owner/repo> --skill <name> --agent claude-code --copy -y` and only after user approval:
  1. `vercel-labs/agent-skills` → `web-design-guidelines`
  2. `cloudflare/skills` → `web-perf`
  3. If React/Next.js: `vercel-labs/agent-skills` → `vercel-react-best-practices` (then `vercel-composition-patterns`, `vercel-react-view-transitions` as needed)
  4. For deployment from a cloud session: `vercel-labs/agent-skills` → `vercel-cli-with-tokens` (no interactive login), or `deploy-to-vercel` locally
  5. For Figma-driven work: the Figma plugin (`figma@claude-plugins-official`) or the `figma/mcp-server-guide` skills `figma-design-to-code` and `figma-implement-motion`
- This project's static-HTML-first pipeline (Taste) gets more from web-design-guidelines and web-perf than from the React-specific Vercel skills. Those two audit any HTML/CSS/JS, and React knowledge is wasted if the site has no React.
- Two of the most-installed vendor skills, agent-browser (1.33M) and hyperframes (1.33M+), are popular for reasons that don't apply here. Browser automation is already covered by Playwright MCP, and video is not in the brief. High install counts are not the same as usefulness for this project.

- No independent security audit of any vendor skill was checked; skills.sh's audit badges could not be read.
- Plugin-only distributions (Stitch's `npx plugins add`, the Figma and Expo plugins) may not be tracked in this project's `skills-lock.json` the way `npx skills add --copy` installs are. Not verified.
