# Skip the leaderboard and fill four gaps

As of 2 November 2026, the most-installed Agent Skills are a short, lopsided list: Vercel's `find-skills` (**4,157,364** skills.sh installs), Matt Pocock's `grill-me` (**1,476,610**), Vercel's `agent-browser` (**1,332,513**) and Anthropic's `frontend-design` (**1,062,579**, plus **1,134,112** Claude Code plugin installs), alongside the two dominant process packs, `obra/superpowers` and `mattpocock/skills` (each about **310K GitHub stars**). Those counts measure repo popularity, not usefulness. skills.sh counts installs per bundle, and bot-like clones with fewer than 30 stars sit in its top 30. This project already holds the ecosystem's leading design skills (Taste is **#72 at 715,989**, Emil's `emil-design-eng` has **408,486**, Impeccable has **378,685**), so almost every popular design skill would duplicate them or fight them for ownership. The real gaps come after the build: **no SEO or metadata guidance at all**, no tool that measures Core Web Vitals, no persuasive-copy skill, and no explicit rule to prove work before calling it done. Four small, permissively licensed skills fill those gaps, three of them confirmed instruction-only: `addyosmani/web-quality-skills` → `seo`, `cloudflare/skills` → `web-perf`, `obra/superpowers` → `verification-before-completion` and `coreyhaines31/marketingskills` → `copywriting`. A fifth, `vercel-labs/agent-skills` → `deploy-to-vercel`, is worth adding only if hosting comes into scope. Security sets the bar for how they get installed: one trojanized campaign on skills.sh reached **1.7M aggregate installs**, researchers bypassed skill scanners, skills.sh's among them, in under an hour, and this project's `-y` install command skips the CLI's advisory audit, so every file must be read before approval. Context cost caps the number: the 16 always-listed skill descriptions already use about **8,228 characters** of a listing budget set at 1% of the context window, so the additions should be paired with hiding two skills this web project never uses. One caveat runs through the whole report: skills.sh itself was unreachable from the research sessions. Install counts come from LinklyAI's daily mirror of skills.sh (snapshot of 2026-11-02) and should be rechecked on skills.sh before approving any install.

## Bundle counting and bot clones distort a 280-million-install leaderboard

The skills.sh directory grew fast. It reached about **1 million skills and nearly 280 million installs** within roughly seven months of its January 2026 launch, and **375 skills (0.04%) account for 62% of installs**. Vercel's own report says the figures "use aggregate registry counters" that do not represent unique people. This comes from secondary coverage, because vercel.com was unreachable ([Vercel](https://vercel.com/blog/state-of-agent-skills)). The counting method matters more than the scale. Installs are deduplicated anonymous telemetry from the `skills` CLI, and they are **bundle-level: installing a repo counts once for every skill in it** ([LinklyAI methodology](https://github.com/LinklyAI/best-skills/blob/main/docs/methodology.md)). That is why all 22 Lark/Feishu skills sit within 1% of each other at about 836K–841K, and why Matt Pocock's repo fills 21 of the top 70 rows. Installs through plugin marketplaces are not counted at all. Superpowers ships mainly as a plugin, so its top skill ranks only **#193 (413,920)** despite **310,912 stars** ([skills-sh.csv, 2026-11-02](https://raw.githubusercontent.com/LinklyAI/best-skills/main/data/2026-11-02/raw/skills-sh.csv)). Worse, about a dozen top-100 entries come from repos with 0–61 stars and 400K–1.2M installs per skill. One example is `101-skills/superpowers`: four skills at about 927K each from a 17-star repo that is an inference.sh media bundle unrelated to obra's project, despite the name ([101-skills/superpowers](https://github.com/101-skills/superpowers)). That pattern fits bot- or CI-driven installs. No source confirms gaming, so this is an inference, but it is enough to rule out rank as a vetting signal.

## The design team owns the top design skills, and its gaps open after the build

The project has **20 skill folders**: Taste, Impeccable, 16 Emil Kowalski skills, `find-skills` and the `/build-website` command. Figma and Playwright MCP are configured, and the demo `site/` is static HTML, CSS and JavaScript ([README.md](/home/user/New-system-/README.md), [CLAUDE.md](/home/user/New-system-/CLAUDE.md)). A grep of every installed skill for SEO, Open Graph, JSON-LD, structured data, meta description, sitemap and robots.txt found **no SEO or metadata guidance**. The only hits were incidental, such as Taste's note that a footer "is … not a sitemap". So the pipeline can produce an award-grade page with no `<title>` strategy, share card or schema. Performance has the same shape. Impeccable's `optimize` reference tells the agent to measure LCP, INP and CLS and to "Compare Lighthouse scores", but it **ships no Lighthouse runner**, and `harden` mentions axe only in passing ([optimize.md](/home/user/New-system-/.claude/skills/impeccable/reference/optimize.md), [harden.md](/home/user/New-system-/.claude/skills/impeccable/reference/harden.md)). Emil's `animation-performance` covers the frame budget for motion, not load time.

Copy is a partial gap. Taste's "5. Write the words" step sets headline lengths from gallery medians, and Impeccable's `clarify` handles UX microcopy, but neither teaches persuasion or conversion structure ([Taste SKILL.md](/home/user/New-system-/.claude/skills/design-taste-frontend/SKILL.md)). Process discipline is the subtler gap. CLAUDE.md demands a Playwright click-through and Taste's measured gate, yet no skill forces the agent to quote proof before saying "done". Deployment has no coverage at all. Several stages that look like gaps are already covered, and adding skills there only adds noise. Browser testing belongs to Playwright MCP and `inspect.mjs`. Design tokens belong to Impeccable's `document`/`extract` and Figma's `get_variable_defs`. Skill authoring is covered by the synced `anthropic-skills:skill-creator`, and code review by Claude Code's bundled `/code-review`, `/security-review` and `/simplify` ([Claude Code skills docs](https://code.claude.com/docs/en/skills)). Because the stack is static HTML, the heavily installed React and Next.js playbooks have nothing to work on here yet.

## A 1.7-million-install trojan shows installs cannot be the vetting signal

The threat is not hypothetical, and it reached skills.sh itself. Zenity Labs described a campaign whose skills **first appeared as clean copies of legitimate upstream skills to build installs, then were trojanized on July 11 under typosquatted names**. The payload was a remote loader that fetched a credential harvester. One family passed 1.7M aggregate installs before Zenity and Vercel disrupted it, and Zenity found "dozens" more malicious skills. These figures come from secondary coverage, because Zenity's post was unreachable ([TechRadar](https://techradar.com/pro/security/experts-warn-malicious-ai-skills-are-hitting-more-victims-than-ever-with-one-family-amassing-1-7-million-downloads), [BusinessWire](https://www.businesswire.com/news/home/20260806707467/en/)). Earlier in the year, Koi Security found **341 malicious skills out of 2,857** on ClawHub, later 824 out of 10,700+, which used fake "prerequisite" installers to drop Atomic Stealer ([The Hacker News](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)). Snyk's ToxicSkills audit of 3,984 skills reported **13.4% with critical issues and 76 confirmed malicious payloads**, per secondary summaries ([Plushcap summary of Snyk](https://www.plushcap.com/content/snyk/blog/snyk-snyk-finds-prompt-injection-in-36-1467-malicious-payloads-in-a-toxicskills-study-of-agent-skills-supply-chain-compromise)). An academic scan of 31,132 skills found **26.1% vulnerable**, and skills that bundle scripts were **2.12× more likely** to be vulnerable ([arXiv:2601.10338](https://www.arxiv.org/abs/2601.10338)). Scanners do not close the gap. Trail of Bits bypassed the ClawHub, Cisco and skills.sh detectors, in three of four cases in under an hour, using whitespace padding, `.pyc` payloads and logic fetched from external documents ([The Hacker News](https://thehackernews.com/2026/06/fake-ai-agent-skill-passed-security.html), [VPNCentral](https://vpncentral.com/?p=251452)).

Anthropic's position is blunt: "Use Skills only from trusted sources", audit every bundled file, and treat skills that fetch from external URLs as high risk, because "even trustworthy Skills can be compromised if their external dependencies change over time" ([Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)). Claude Code adds a sharper warning. A project skill's `allowed-tools` frontmatter is applied **even in a folder the user never trusted**, so a skill can grant itself tool access ([Claude Code skills docs](https://code.claude.com/docs/en/skills)). Microsoft's `playwright-cli`, for example, pre-grants `Bash(npx playwright:*)` ([SKILL.md](https://github.com/microsoft/playwright-cli/blob/c2d8d19/skills/playwright-cli/SKILL.md)).

This project's install path has three blind spots worth knowing. First, the `skills` CLI fetches Gen Agent Trust Hub, Socket and Snyk verdicts, but its source says the information is "advisory only" and that a failed fetch "never blocks installation". The `-y` flag in CLAUDE.md's command skips the confirmation prompt, and in a cloud session where skills.sh is blocked, the audit table simply does not appear ([add.ts](https://github.com/vercel-labs/skills/blob/92a9a34/src/add.ts)). Second, `skills-lock.json` records a SHA-256 `computedHash` over every file path and its contents, which makes later edits on disk visible, but **it records no commit SHA**. This project's 18 lock entries carry no `ref`, and Impeccable, which was copied by hand, is not in the lock at all ([local-lock.ts](https://github.com/vercel-labs/skills/blob/92a9a34/src/local-lock.ts), [skills-lock.json](/home/user/New-system-/skills-lock.json)). Third, nothing on disk protects against a skill that fetches its rules at runtime or runs `npx …@latest`. The files can stay byte-identical while the behaviour changes.

The installed `find-skills` vets candidates by install count, stars and source reputation only ([find-skills SKILL.md](/home/user/New-system-/.claude/skills/find-skills/SKILL.md)). That is too weak on its own, so the vetting used for this shortlist runs in a stricter order. Confirm the exact `owner/repo`, character by character, against the canonical publisher. Then list every file: instruction-only skills are the lowest risk, and any script gets read in full. Check frontmatter for `allowed-tools`, hooks and `` !`command` `` injection, and check the body for remote fetches and `@latest` packages. Test the description's triggers against Taste, Impeccable and Emil. Only then use installs, stars, recent pushes and skills.sh audit tabs as tie-breakers. On the commits read, `seo`, `verification-before-completion` and `copywriting` pass the file and capability checks. `web-perf` was read only as far as its size and description, so its body still needs a full read. `deploy-to-vercel` carries the caveats listed in the shortlist. None was installed or run during the research.

## Every new description spends a listing budget the project has nearly used

Anthropic's own documentation contains two statements that are easy to read as contradictory. The platform docs estimate about **100 tokens of always-loaded metadata per skill** and say you can "install many Skills without context penalty" ([Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)). Claude Code, however, caps the whole skill listing at **1% of the model's context window**. When the listing overflows, it "drops descriptions starting with the skills you invoke least, which removes the keywords Claude needs to match your request" ([Claude Code skills docs](https://code.claude.com/docs/en/skills)). Both hold. The per-skill cost is small, but the total is bounded, and overflow fails silently: a rarely used skill such as `break-ui` or `apple-design` simply stops triggering. This repo already lists 16 model-invocable descriptions totalling about **8,228 characters**, and the session listing also carries built-in and synced skills (about 40 in all). At roughly 4 characters per token, 1% of a 200K window is about 8K characters. That is an estimate, and `/doctor` and `/context` give the real figure. Two of the always-listed skills, `write-swift` (482 characters) and `animate-expo` (523), serve native apps this web pipeline never builds.

Outside data points the same way. A Hugging Face analysis found **46.3% of public skills are duplicates or near-duplicates**, and a MindStudio guide calls over-installation the most common mistake, suggesting 5–8 tools per project. Both are known only through search summaries ([Hugging Face](https://huggingface.co/blog/zhongshsh/agent-skills-analysis), [MindStudio](https://www.mindstudio.ai/blog/claude-code-skills-common-mistakes-guide)). Trigger collisions cost more than tokens. `web-design-guidelines` fires on "review my UI", "check accessibility" and "audit design", `copy-editing` on "polish this", and `web-quality-audit` on "audit my site". All of these are words CLAUDE.md assigns to Impeccable. Reviewers also warn that stacking Superpowers on another planning process "can give Claude two competing processes for the same request" ([buildthisnow](https://www.buildthisnow.com/blog/guide/mechanics/best-claude-code-setups-2026)). The practical rule is a net-zero budget. Add only skills whose descriptions use words no installed skill claims. Set `write-swift` and `animate-expo` to `"name-only"` through Claude Code's `skillOverrides` setting to free about 1,000 characters. Re-check `/doctor` after each addition.

## Conclusion

For a mature design stack, the ecosystem's value lies in adjacent disciplines, not in more taste. The leaderboard steers the other way, because bundle counting and clones reward repos, not fit. The deciding factors were three things install counts cannot show. Are the skill's trigger words free, or can one CLAUDE.md line fence them? Is it instruction-only? Can it be pinned? The four core picks meet all three, with `web-perf`'s body still to be read in full. The deploy skill is conditional because its `@latest` CLI fails the pinning test. `web-design-guidelines` fails pinning outright, because it fetches its rules from another repo's `main` branch at runtime, and the art-direction skills fail the ownership test, however many installs they have.

The less obvious takeaway is that ownership rules matter as much as the installs. Each addition below needs one CLAUDE.md line saying which stage it serves and who leads, or it will quietly compete with Taste or Impeccable. The lock file also needs help: recording upstream commit SHAs in README (as the project already does for Taste and Emil) and treating any `computedHash` change after `npx skills update` as a trigger to re-vet would close the pinning gap the CLI leaves open.
